# Complete configuration and symbology reference

This document describes the configuration currently implemented by **Pure PHP WMS**. For a first deployment follow [INSTALLATION.md](../INSTALLATION.md); for end-to-end examples see the [README](../README.md).

All configuration files are **UTF-8 JSON without comments**. Source, dataset, service and style identifiers must match `^[a-z][a-z0-9_-]{0,63}$` (start with a lowercase letter; up to 64 characters). Layer names use the same pattern. Layer names and feature-property keys are **case-sensitive**. File names are local, not URLs.

## 1. Directory structure and concepts

| Location | Responsibility |
|---|---|
| `config/server.json` | Public endpoint URL, fallback service, CORS and resource budgets |
| `config/sources.json` | Definition of original, locally imported source files |
| `config/services/NAME.json` | One independent, selectable WMS service |
| `config/styles/NAME.json` | Reusable named style / symbolizer |
| `sources/` | Original Shapefile/GeoJSON/GeoPackage sources needed during import |
| `data/NAME.sqlite` | Imported dataset; generated by CLI, **not hand-edited** |
| `resources/` | Local PNG icons and TTF fonts |
| `cache/` | PNG cache entries and worker lock files |
| `public/wms.php` | Public HTTP GET endpoint |

A **source** ID is used to import a **dataset** of the same name. A **layer** within a service references the dataset and a list of existing **style** IDs. A **service** name is the filename without `.json`, selected through the `MAP` request parameter. Different services can reuse the same datasets and styles without duplicating them.

## 2. `config/server.json`

A typical installation uses:

```json
{
  "base_url": "https://maps.example.org/wms.php",
  "default_service": "demo",
  "max_side": 2048,
  "max_pixels": 2097152,
  "max_features": 5000,
  "max_vertices": 250000,
  "max_seconds": 10,
  "max_parallel": 3,
  "cache_slots": 64,
  "cache_ttl": 3600,
  "cors_origins": ["*"]
}
```

| Property | Meaning and validation |
|---|---|
| `base_url` | Absolute HTTP(S) URL to `wms.php`, no query, fragment or credentials. Published in capabilities |
| `default_service` | Valid service ID used when `MAP` is absent; shipped as `demo` |
| `cors_origins` | List of allowed browser origins. `["*"]` allows credential-free cross-origin GETs; `[]` allows no cross-origin reads |
| `max_side` | Maximum width or height; shipped as 2048; allowed setting 64–4096 |
| `max_pixels` | Maximum width × height; shipped as 2,097,152; allowed setting 4,096–4,194,304 |
| `max_features` | Maximum number of visible features processed per request; shipped as 5000; allowed setting 1–50,000 |
| `max_vertices` | Maximum transformed vertices; shipped as 250,000; allowed setting 100–1,000,000 |
| `max_seconds` | Cooperative rendering time budget in seconds; shipped as 10; allowed setting 1–60 |
| `max_parallel` | Maximum simultaneous admitted rendering requests per installation; shipped as 3; allowed setting 1–16 |
| `cache_slots` | Number of PNG cache slots; shipped as 64; allowed setting 0–2048; 0 disables the cache |
| `cache_ttl` | Cache lifetime in seconds; shipped as 3600; allowed setting 0–86,400; 0 disables the cache |

The cooperative time budget checks the application loop but does **not** interrupt an individual blocking library/GD call. Retain a sensible PHP `max_execution_time` at the web-server level. The renderer also uses a bounded polygon scanline work budget.

`cache_slots` limits file **count**, not disk bytes. At 2,097,152 pixels, a worst-case uncompressed RGBA image is about 8 MiB; 64 poorly compressible cached images could approach 512 MiB. Tight hosting should lower `cache_slots` or `max_pixels`. Old `render-*` temporary files can be removed when you are certain the creating processes ended. Do **not** delete or replace active `worker-*.lock` files.

CORS is **not access control**: use Apache auth or network restrictions to protect nonpublic services. There is no credential CORS or authorization-header preflight implementation.

## 3. `config/sources.json`: source formats

Example combining all supported import types:

```json
{
  "protected_areas": {
    "file": "protected_areas.shp",
    "crs": "EPSG:25832",
    "encoding": "Windows-1252"
  },
  "stations": {
    "file": "stations.geojson",
    "crs": "EPSG:4326"
  },
  "administrative_areas": {
    "file": "regions.gpkg",
    "table": "areas",
    "crs": "EPSG:25832"
  }
}
```

| Property | Usage |
|---|---|
| `file` | Required local source filename under `sources/`; not a path traversal, URL or remote file |
| `crs` | Explicit source CRS: `EPSG:4326`, `CRS:84`, `EPSG:3857`, `EPSG:25832` or `EPSG:25833` |
| `encoding` | Shapefile DBF character encoding (e.g. `UTF-8`, `Windows-1252`, `CP850`); defaults to UTF-8 |
| `table` | For GeoPackage: exact simple-feature vector table name |

Source coordinates are always read as **x,y**. In geographic source data that means **longitude,latitude** regardless of the WMS EPSG:4326 BBOX axis order. GeoPackage's CRS metadata must agree with the explicit `crs` setting; Shapefile `.prj` / `.cpg` are **not automatically parsed**. Only simple DBF column types `C`, `N`, `F`, `D` and `L` are supported; preprocess memo/binary columns. Long numeric identifiers should be exported as text to avoid floating-point precision loss.

**Import limits:** 256 MiB source file; Shapefile SHP/DBF are streamed record by record; 1,000,000 features; 5,000,000 vertices across the dataset; 1,000,000 vertices in one GeoJSON/WKB geometry; 64 KiB attributes per feature. SHP record bounds are checked before decoding: at most 1 MiB binary content, 20,000 points and 1000 parts per record, with at most 1,000,000 records including null/deleted entries. Valid Z/M arrays are skipped after structural validation because output is 2D. A publishable feature is limited to **20,000 vertices and 1 MiB geometry JSON**. These are protective limits, not a guarantee that pathologically crafted input cannot exhaust memory. Import only trusted administrative sources; simplify, split or re-export larger data in your GIS.

Imported data is normalized into `data/NAME.sqlite` as EPSG:4326 JSON geometry, JSON properties and an SQLite RTree index. Dataset imports are locally atomic. Each successful import creates a new revision, used for automatic cache invalidation.

## 4. `config/services/NAME.json`: public services and layers

A complete two-layer service:

```json
{
  "title": "Environmental maps",
  "abstract": "Regional environmental information",
  "fees": "none",
  "access_constraints": "none",
  "layers": {
    "protected_areas": {
      "title": "Protected areas",
      "abstract": "Protected polygons",
      "dataset": "protected_areas",
      "styles": ["protected_area", "protected_area_contrast"],
      "queryable": true,
      "query_fields": ["NAME", "TYPE"]
    },
    "stations": {
      "title": "Monitoring stations",
      "dataset": "stations",
      "styles": ["monitoring_stations"],
      "queryable": true,
      "query_fields": ["NAME", "STATUS"]
    }
  }
}
```

This example assumes source IDs `protected_areas`, `stations` and style JSON files `protected_area.json`, `protected_area_contrast.json`, `monitoring_stations.json` already exist.

| Service property | Meaning |
|---|---|
| `title` | Required public title |
| `abstract` | Optional descriptive text |
| `fees` | Optional fees information; defaults to `none` |
| `access_constraints` | Optional disclosure; defaults to `none`; **does not enforce** authorization |
| `layers` | Required, nonempty object mapping public layer IDs to layer definitions |

| Layer property | Meaning |
|---|---|
| `title` | Required public layer title |
| `abstract` | Optional layer description |
| `dataset` | Required registered source ID; matches `data/NAME.sqlite` |
| `styles` | Required nonempty list of valid style IDs; **first is default** |
| `queryable` | Boolean, default `true`; enables GetFeatureInfo |
| `query_fields` | **Required explicit allowlist** of returned property names, including when `queryable` is false |

The response includes feature geometry in JSON even when the property allowlist is small. To disable querying use `"queryable": false, "query_fields": []`. Labels can expose data too; carefully select `label_field` when working with nonpublic properties.

The service-file name defines `MAP=environment` for `config/services/environment.json`. To add a **layer** to this service, add another member of its `layers` object. To add a **separate WMS service**, create another service JSON. Layer list order controls listing in GetCapabilities. Clients choose render order with `LAYERS`, independently of configuration order.

## 5. `config/styles/NAME.json`: all symbology fields

A style is applied to actual geometry; `legend_geometry` affects the generated **legend sample only**.

| Property | Meaning and default |
|---|---|
| `title` | Human-readable name in GetCapabilities / legends |
| `legend_geometry` | `point`, `line`, `polygon`; default `point` |
| `fill` | Fill color `#RRGGBB` or `#RRGGBBAA` |
| `stroke` | Line / outline color in the same formats |
| `stroke_width` | Integer width 0–16 pixels; default 1; 0 suppresses line/outline on supported shapes |
| `symbol` | Built-in point shape: `circle`, `square`, `triangle`, `diamond`, `cross`; default `circle` |
| `size` | Built-in point size or scaled PNG icon width/height, integer 1–128 pixels; default 12 |
| `icon` | Optional local PNG filename from `resources/`; takes precedence over `symbol` for points |
| `label_field` | Case-sensitive attribute to display as a label; omitted means no labels |
| `font` | Local TTF file in `resources/`; default `DejaVuSans.ttf` |
| `font_size` | Integer FreeType point size 6–48; default 11 |
| `label_color` | Text color |
| `halo_color` | Label-outline color; defaults to white |
| `halo` | Label outline width 0–4 pixels; default 1 |
| `min_scale` | Visible from this scale denominator **inclusive**; default 0 |
| `max_scale` | Invisible from this scale denominator **inclusive**; default unlimited |
| `rules` | Ordered list of up to 32 attribute-classification rules |

The `#RRGGBBAA` notation uses **last-byte alpha**: `00` is transparent, `ff` opaque. Example: `#22994480` is semi-transparent green. Width/size units are map **image pixels**, not map units.

The scale denominator is calculated from horizontal ground resolution using the WMS standard pixel size **0.28 mm**. Geographic projections use the specified standard meters-per-degree factor; this is **not** an exact local ground-scale calculation.

### 5.1 Polygon and line styles

```json
{
  "title": "Semi-transparent protected polygons",
  "legend_geometry": "polygon",
  "fill": "#75b76b70",
  "stroke": "#2b6933",
  "stroke_width": 2,
  "label_field": "NAME",
  "font_size": 12,
  "halo": 2
}
```

```json
{
  "title": "Walking routes",
  "legend_geometry": "line",
  "stroke": "#c99055",
  "stroke_width": 4,
  "label_field": "NAME"
}
```

Polygon holes are respected: underlying layers remain visible through them. Polygons and lines are drawn from their supplied vertices without geodesic edge densification.

### 5.2 Point symbols

```json
{
  "title": "Monitoring sites",
  "legend_geometry": "point",
  "symbol": "diamond",
  "size": 16,
  "fill": "#4274ad",
  "stroke": "#254a76",
  "stroke_width": 2,
  "label_field": "NAME",
  "font": "DejaVuSans.ttf",
  "font_size": 11,
  "label_color": "#1a2836",
  "halo_color": "#ffffff",
  "halo": 2
}
```

Available built-in shapes: `circle`, `square`, `triangle`, `diamond`, `cross`. Crosses are drawn from strokes; fill does not apply to them.

### 5.3 Custom PNG markers and TTF labels

Put `warning.png` and `MyFont.ttf` inside `resources/` and reference them by **filename only**:

```json
{
  "title": "Warnings",
  "legend_geometry": "point",
  "icon": "warning.png",
  "size": 24,
  "label_field": "NAME",
  "font": "MyFont.ttf",
  "font_size": 12
}
```

PNG icons must be **512 × 512 pixels or smaller**, no larger than **1 MiB**; transparent backgrounds are recommended. Icons are rendered at `size × size`, so use square assets to avoid distortion. Only local **PNG** icons and local **TTF** fonts are accepted. SVG, HTTP URLs, remote font fetches and uploads are not supported. Resource filenames cannot contain path separators; the server checks real paths.

Label candidates are collected after geometries are rendered. Labels are horizontal, try up to three positions around the feature, use collision checks within **one image**, and may be dropped when overlapping or outside the image. Maximum **1500** label candidates per request, truncated to **80 Unicode characters** each. There is no consistent labeling across independently generated WMS tiles, no complex-script shaping guarantee and no curved/rotated labels.

### 5.4 Class rules

```json
{
  "title": "Site status",
  "legend_geometry": "point",
  "symbol": "circle",
  "size": 12,
  "fill": "#367ab8",
  "stroke": "#173d60",
  "label_field": "NAME",
  "max_scale": 250000,
  "rules": [
    {
      "field": "STATUS",
      "equals": "critical",
      "symbolizer": {
        "symbol": "triangle",
        "fill": "#d34836",
        "size": 18,
        "icon": "warning.png"
      }
    },
    {
      "field": "STATUS",
      "equals": "warning",
      "symbolizer": {
        "fill": "#edb145",
        "size": 15
      }
    }
  ]
}
```

Each rule requires a `field`, a scalar `equals` value, and a `symbolizer` object containing only properties to override. Rules run **in order** and the **first match wins**. Only scalar properties can match; arrays and objects cannot. Equality compares string representations, not ranges, regex or SQL predicates. `min_scale` and `max_scale` may also be overridden in rules. If a base style already defines `icon`, a matching rule that only changes `symbol` will **not** remove that icon; define separate styles as needed. The legend generator draws the base style and an entry for each rule, labeled with its `equals` value.

### 5.5 Alternative styles and layer requests

Create both `config/styles/standard.json` and `config/styles/contrast.json`. Set a layer to `"styles": ["standard", "contrast"]`. The first style is its default. A WMS request may explicitly specify `STYLES=contrast` for one layer. For two layers, `LAYERS=protected_areas,stations&STYLES=contrast,` uses `contrast` for the first and the default for the second. `STYLES=` applies every default.

## 6. WMS protocol, parameters and information disclosure

Only **HTTP GET** is supported. Query parameter *names* are case-insensitive; duplicates, array-style names and embedded NUL bytes are rejected. Maximum query-string length is 8192 bytes. `GetCapabilities` requires `SERVICE=WMS`; the other operations may omit SERVICE but must use `VERSION=1.3.0`. The server only offers WMS 1.3.0 and negotiates syntactically valid version requests to it for GetCapabilities.

- **GetCapabilities:** `SERVICE=WMS&REQUEST=GetCapabilities&VERSION=1.3.0&MAP=demo`; returns XML capabilities and layer/style metadata.
- **GetMap:** `REQUEST=GetMap&VERSION=1.3.0&MAP=demo&LAYERS=land,routes,places&STYLES=&CRS=CRS:84&BBOX=11.28,48.18,11.39,48.245&WIDTH=1000&HEIGHT=700&FORMAT=image/png&TRANSPARENT=TRUE`.
- **GetFeatureInfo:** repeat map parameters and add `QUERY_LAYERS=places&I=500&J=350&INFO_FORMAT=application/json&FEATURE_COUNT=5`. Also supports `text/plain`.
- **GetLegendGraphic:** `REQUEST=GetLegendGraphic&VERSION=1.3.0&MAP=demo&LAYER=places&FORMAT=image/png`; optional `STYLE`.

`EPSG:4326` **WMS BBOX** uses latitude,longitude. `CRS:84` uses longitude,latitude. Example equivalent boxes: `CRS:84 BBOX=11.28,48.18,11.39,48.245` and `EPSG:4326 BBOX=48.18,11.28,48.245,11.39`.

GetFeatureInfo requires `QUERY_LAYERS` (subset of the visible map layers), `I`, `J` pixel coordinates and an allowed `INFO_FORMAT`. `FEATURE_COUNT` is **per queried layer**; default **1** for missing/invalid/nonpositive values, capped at **100 per layer**. Hits are sorted by proximity to the selected pixel. Points use a tolerance of at least 5 pixels or half the icon size; lines at least 3 pixels. Polygons respect holes. Icon transparency is **not** alpha-hit-tested; hit detection uses point geometry.

Only allowed property names are returned by GetFeatureInfo, **but geometries are still present** in JSON. Queryable layers may reveal selected geometries, even when no properties are allowed. HTTP uses ETag and `Cache-Control: no-cache`; errors use WMS XML service exceptions.

Unknown extension parameters such as SLD, FILTER, TIME or ELEVATION are accepted but **ignored** (not evaluated); no remote references are fetched. Supported exception format is XML only; `UPDATESEQUENCE`, XML POST and in-image exceptions are not implemented.

## 7. Operational boundaries and common mistakes

- Supported coordinates: regionally suitable EPSG:4326, CRS:84, EPSG:3857, EPSG:25832/25833; geographic latitude ±85.05112878°; no dateline wrapping or polar services.
- Imported geometries must already be topologically valid; the importer does not repair self-intersections.
- Geometry edges are joined between input vertices; densify long sparse edges in a GIS when accuracy matters.
- ETRS89/WGS84 transformations are suitable for cartographic use, not epoch-accurate surveying.
- No raster services, curved geometry, arbitrary projection definitions, automatic map tile grids or vector WFS.
- The active renderer budgets and local PHP/Apache limits determine production capacity; test representative inputs.

After modifying source files, run `php bin/console.php import NAME`; after modifying service or style JSON run `php bin/console.php validate`; after changing application code clear the map cache. Publish changed SQLite files safely (atomic rename or versioned dataset switch); never transfer them over the active name byte by byte.

### Runtime hardening

GetFeatureInfo applies a conservative 64-pixel spatial search radius before the actual geometry/style hit test. This radius covers the largest supported point symbol. Closest results are retained as serialized features with an aggregate 8 MiB payload budget; oversized responses produce a controlled 503. Text responses omit geometry from their retained representation. Duplicate query-layer names are processed once.

Cache entries are opened before checking age/key, avoiding pathname races with cleanup. Missing or invalid entries are cache misses. Failed writes are logged and do not discard a rendered map; render admission still needs accessible `worker-*.lock` files. Do not delete lock files during operation.
